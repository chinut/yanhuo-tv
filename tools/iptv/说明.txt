# IPTV 源扫描器 —— 使用说明

**目标**：测出你家宽带下**真正能看**的直播源，把结果发回来。

为什么必须在**你家**的电脑上跑：IPTV 源是**运营商 + 地区**限定的。
电信的源在移动宽带上多半不通，广东的源在北京可能不通。
所以"在别人电脑上测可用"没有意义。

---

## 一、怎么用（三步）

### 1. 装 Python（只需一次）

打开 https://www.python.org/downloads/ 下载安装。

> ⚠️ **安装时一定要勾选 `Add Python to PATH`** 这个选项，
> 否则双击 `run.bat` 会说找不到 Python。

### 2. 双击 `run.bat`

- 第一次会自动装组件（约 30MB，一两分钟）
- 然后开始扫描，屏幕会一直滚动显示进度
- **不是卡住了** —— 每个源要真解一遍视频，慢是正常的
- 通常 **10~40 分钟**

### 3. 把 `iptv_result.json` 发回来

扫描结束后在同一文件夹里会生成两个文件：

| 文件 | 用途 |
|---|---|
| **`iptv_result.json`** | **这个发给我**，我内置进 App |
| `iptv_可用源.m3u` | 也可以直接填进 App 试（设置 → 电视直播 → 自定义直播源地址） |

## 二、它到底在测什么（为什么可信）

我前面几轮踩过的坑，全在这里纠正了：

| 我之前用的错误判据 | 后果 |
|---|---|
| HTTP 200 就算可用 | 央视加密源也能取到，但**永远花屏** |
| ffmpeg 能解码就算可用 | **音频源、灰帧**也能通过 |
| 解出一帧就算可用 | **灰色空帧**也能通过（真实踩过） |

**现在唯一使用的判据**：

1. 有视频轨道
2. 解出 3 帧
3. **std > 10** —— 画面有细节，不是纯色/灰屏
4. **帧差 > 1.5** —— 画面在动（直播一定是动的）

区分度很大：

```
央视加密源（花屏）:  std 0.0~1.7    帧差 0.00
正常 IPTV 源:        std 23~60      帧差 2~47
```

## 三、如果结果是 0 个可用

很可能说明**公开源列表在你这条宽带上都不通**（这很常见）。

解决办法：**用你自己的源**

```
run.bat 里改成：
    iptv_scan.py --list "你自己的播放列表.m3u"
```

你自己的源可以从这些地方来：

- **宽带运营商**送的 IPTV 播放列表（打电话问客服，或看光猫/机顶盒说明书）
- 朋友给的、同城同运营商的列表
- 网上找到的、**标注了你所在地区/运营商**的列表

> 同城同运营商的源命中率最高。跨市的源**有时也能用**，
> 所以这个工具会把所有候选都实测一遍，能用的都留下。

---

## 四、常用参数

```bat
REM 只测央视（名字里含 CCTV 的）
iptv_scan.py --filter CCTV

REM 用你自己的列表
iptv_scan.py --list "D:\我的源.m3u"

REM 网络慢就调小并发
iptv_scan.py --jobs 3

REM 每个频道多测几个地址（默认 6）
iptv_scan.py --max-per-channel 12
```

## 五、常见问题

**Q: 提示取不到任何源列表？**
说明访问 GitHub 受限。用 `--list` 指定你自己下载好的 m3u 文件。

**Q: 跑到一半关了窗口？**
没关系，重跑一次。已经测过的会重新测（还没做断点续传）。

**Q: 为什么这么慢？**
每个源都要真的解 3 帧视频，还要等超时。
600 个源大约 20~40 分钟。**这是为了保证结果可信** ——
之前"快速判断"的结果就是一堆花屏源。

**Q: 会不会占满带宽？**
会占一部分（同时测 6 个流）。想边上网边跑就用 `--jobs 2`。
