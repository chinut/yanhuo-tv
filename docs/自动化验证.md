# 自动化验证工具

## 这个工具解决什么问题

之前每一版改完都**没法自己验证**，只能打包交给用户在真机上试 —— 用户成了测试员，
而且一次要等打包、装机、试。根因是验证手段不可靠：

| 手段 | 为什么不可靠 |
|---|---|
| `am start --es dsh_route vod` | MainActivity 是 `singleTop`，Activity 已存在时 `am start` **复用实例**、`onCreate` 不再执行 → extra 永远读不到（"明明带了 `--es` 却是 null"） |
| `input keyevent` 盲按方向键 | 首页方向键被直播块接管（上下 = 换台），走不到影视板块；焦点经常落在搜索框等别处 |

`verify.ps1` 用两条可靠通道替换它们。

## 两条通道

### 1. 广播跳转（替代 `am start --es`）

```powershell
adb shell am broadcast -a com.chinut.bawantv.DEBUG_ROUTE --es route vod
```

路由：`home` / `live` / `vod` / `settings`

每次都会送达，直接切到目标板块。接收器在 `BawanRoot` 里动态注册。

> ⚠️ 两个容易踩的坑（都踩过）：
> - Android 14 起**必须**显式声明 `RECEIVER_EXPORTED` 或 `RECEIVER_NOT_EXPORTED`，
>   裸 `registerReceiver` 直接抛 `SecurityException`，App 秒崩；
> - 必须是 **`EXPORTED`** —— `adb shell` 的 UID 和应用不同，
>   `NOT_EXPORTED` 会把脚本发来的广播丢掉。

### 2. HTTP 遥控（替代盲按 + 猜状态）

复用设置页里那个"手机网页调试"服务（默认 8899），经 adb 端口转发到本地：

```powershell
adb forward tcp:18899 tcp:8899
```

| 接口 | 用途 |
|---|---|
| `GET /api/remote/ping` | 探活 |
| `GET /api/remote/status` | **当前在哪个板块**（`screen` 字段）—— "我到底在哪"的唯一可靠来源 |
| `POST /api/remote/key` | 发按键（`key=down` / `keyCode=20`） |

## 模拟器掉线了怎么办

**不用重启电脑。** 先分清是哪种情况：

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb devices` 空，但 `Get-Process qemu*` **有**进程 | adb 服务断了 | `adb kill-server` 再 `adb start-server`，几秒就好 |
| `adb devices` 空，`Get-Process qemu*` **也没有**进程 | 模拟器自己崩了（内存不足 / 被反复强杀） | 重新启动模拟器即可 |

一条命令搞定第二种：

```powershell
$code = [System.IO.File]::ReadAllText("tools\emu.ps1",[System.Text.Encoding]::UTF8)
& ([scriptblock]::Create($code))
```

脚本会：启动 AVD → 等设备上线 → 等系统启动完成。
如果卡死但进程还在，加 `-Force` 先清理再启动。

> 模拟器只是一个普通应用进程，**不需要重启电脑**。
> 真正需要重启电脑的情况极少（adb 驱动被别的软件占住、USB 子系统异常等）。

## 怎么跑

```powershell
cd G:\android\AndroidTV

# ⚠️ 本机 ExecutionPolicy 禁止直接跑 .ps1，用 scriptblock 绕行：
$code = [System.IO.File]::ReadAllText("tools\verify.ps1",[System.Text.Encoding]::UTF8)
& ([scriptblock]::Create($code)) -Action check
```

其他用法：

```powershell
& ([scriptblock]::Create($code)) -Action nav  -Route vod    # 只跳转
& ([scriptblock]::Create($code)) -Action shot -Route vod    # 跳转 + 截图
```

**前置条件**：应用已启动，且设置页里「允许手机调试」是打开的（显示"服务运行中"）。

> 脚本会**自动把应用拉到前台**。这一步是必需的，不能只看 `pidof`：
> 应用被返回键退回桌面后进程**还在**，但 Android 会**冻结后台进程**，
> 事件循环停转 → 调试服务不响应，HTTP 连接全部停在 `CLOSE_WAIT`，脚本超时。
> 所以判断标准是"**能不能 ping 通**"，而不是"进程在不在"。

## 检查项覆盖什么

只覆盖**曾经真的坏过**的路径 —— 每一条都对应一个真实 bug，不是为了刷覆盖率：

| 检查 | 对应的真实故障 |
|---|---|
| 应用进程存活 | — |
| 广播跳转到 home/live/vod/settings | `am start --es` 不可用 |
| 影视：进入详情页 | "没有可返回可播放的剧集"误报、详情页崩溃 |
| 影视：起播不崩溃 | ExoPlayer 缓冲参数写反 → **所有影视一播就闪退** |
| 返回键不吞键、逐层退出 | 首页 `BackHandler` 的 `else -> Unit` 把返回键吞掉，退不出 App |
| 整轮无 `FATAL EXCEPTION` | "进程还在"不等于"没崩过"（可能在崩溃重启前后读到 PID） |

**加新检查项时请遵守同样的原则**：能对应到一个具体故障，而不是"顺手多测一点"。

## 已知限制

- **只能验证"没崩 / 到了哪个界面"**，验证不了手感类参数
  （阻尼斜率、缓冲时长、动画流畅度）—— 那些**必须真机**。
- 模拟器是 x86 + 软件渲染，**性能表现不代表电视**。
  直播硬解是否真的生效，要看真机上的 CPU 占用和流畅度。

## 踩坑记录：不要用 Compose 的 Dialog

**症状**：更新框弹出后，遥控器能"看到"按钮，但按确定毫无反应，方向键也移不动焦点。

**根因**：Compose 的 `Dialog` 会开一个**独立窗口接管按键**，
`MainActivity.dispatchKeyEvent` 收不到 —— 而本应用整套遥控器操作
（方向键 / 确定键 / 返回键 / 菜单键）全部依赖那个 `dispatchKeyEvent`
转发给自定义的 `TvFocusManager`。按键进不来，Dialog 里的 `tvFocusable`
就永远收不到输入。

同理，`FocusRequester`（Compose 原生焦点）和这套自定义焦点系统**不通用**，
用它定位初始焦点同样无效。

**结论**：应用内所有"弹窗"都应做成**主合成树里的浮层**，不要用 `Dialog`。
（`UpdateDialog` 已改。其它仍在用 Dialog 的界面若出现同类症状，按同样思路处理。）

**验证时的实测判据**（很有效，值得复用）：

1. 在弹窗打开状态下按方向键，截图看焦点框**是否移动**
2. 看 logcat 有没有 `BawanFocus` 的日志

两者都没有 → 按键根本没进自定义焦点系统。

## 模拟器卡死的处理

`adb shell screencap` + `adb pull` 会**永久挂起**（超过 30 秒无响应），
`adb shell dumpsys window` / `dumpsys activity` 同样容易挂。

- 判断方法：`adb devices` 仍显示 `device`，但 screencap 不返回 → 图形栈卡住
- 处理：重启模拟器（`tools/emu.ps1 -Force`）
- 规避：优先用 `adb exec-out screencap -p > 文件`，并给它套超时
