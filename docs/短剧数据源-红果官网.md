# 短剧数据源：红果短剧官网（已验证可用）

**结论：短剧可以做，而且整个数据层不需要 WebView。**

> ⚠️ 本文档第一版对链路的描述**不准确**，已按实测重写。
> 之前写"播放页 HTML 里有 main_url，链路已通"，但那只验证了**一次 Python 请求**，
> 没有验证在真实浏览器环境下的行为 —— 实测用浏览器打开时视频会变成
> `blob:`（MSE），`main_url` 反而取不到。教训：**一次成功不等于可复现**。

## 一、为什么不用那个短剧 App

| 尝试 | 结果 |
|---|---|
| 读它的 Java 源码 | Java 层只有 `MainActivity` + `R.java`，逻辑全在编译产物里 |
| 静态分析 `.so` | 能拿到接口路径的**格式串**，但签名算法是 Go 机器码，取不出来 |
| 直接请求接口 | 红果 404、zzzznnn 403、9ddm 404、qmplaylet 404、ygdj7 反爬 |
| 抓包（mitmproxy） | **App 有证书固定**（`libduanju_core.so` 里 `x509` 365 处、`RootCAs`），不认用户 CA → 0 条日志 |
| 整个塞进我们的 App | Flutter 编译产物、单架构 64MB、minSdk 26（我们 23） |

**抓包失败的证据**（用户截图里的报错）：

```
Get "https://hongguoduanju.com/category/real-drama?...":
tls: failed to verify certificate: x509: certificate signed by unknown authority
```

—— 这就是证书固定。**但它同时暴露了真实网址**，于是有了下面这条路。

## 二、可行的方案：爬红果短剧官网

那篇文章的关键是：**网址是公开的，而且服务端渲染（SSR），HTML 里就有数据。**

### 链路

```
① 分类页   https://hongguoduanju.com/category/real-drama
             解析 href="/detail?series_id=xxx"        → 剧集列表

② 详情页   https://hongguoduanju.com/detail?series_id=xxx
             解析 href="/player/{sid}/{eid}"           → 全部分集
             <title> 里有剧名，"全72集" 里有集数
             海报 URL 也能取到

③ 播放页   https://hongguoduanju.com/player/{sid}/{eid}
             HTML 里嵌了：
                 "video_player_info": {
                     "main_url": "https://v26-hgweb.qznovelvod.com/...",
                     "duration": 112.246,
                     "width": 720, "height": 1280,
                     "poster_url": "..."
                 }
             main_url 就是可直接播放的视频地址
```

### 实测证据

```
播放地址实测：
    HTTP 206
    Content-Type: video/mp4
    前 16 字节: 000000206674797069736f6d      ← "ftypisom"，标准 MP4
    时长 112 秒，分辨率 720x1280（竖屏）
```

**是直接的 MP4 文件，不需要 m3u8、不需要解密、不需要签名。**
ExoPlayer 直接就能播（我们已经有现成的播放器）。

### 其它可用的分类

从首页拿到的分类路径（都可直接访问）：

```
/category/real-drama        真人剧（还有子分类：action-adventure / clan /
                            comeback / comedy / costume / family ...）
/category/comic-drama       漫剧
/category/ai-drama          AI 剧
/rank/hot-drama             热榜
/rank/hot-real-drama        真人剧热榜
```

### 黄果剧场（备选源）

```
https://huangguo.video/videos        列表（/series/{id} 形式）
```
也是公开可访问的，可作为第二个源。但它的详情页 `/series/220` 我试的那个
返回 404，需要重新取样确认 URL 形态。

## 三、实现要点

### 复用现有架构

短剧和影视在交互上是**同一件事**（海报墙 → 详情 → 选集 → 播放），
所以走影视那套组件，不另写 UI —— 电视内存本来就紧（已占 250MB+），
多一套界面等于多一份图片缓存和组合开销。

### 需要新写的

1. **`HongguoScraper`** —— 三个页面的解析（正则 + HTML 解码）
2. **短剧的 `MovieAggregator` 对等物** —— 目前是 ddys 专用，短剧要另接
3. **自动连播** —— 一集播完自动下一集（短剧的核心体验）
4. **详情页剧集密集网格** —— 现在影视是横排按钮，短剧几十上百集需要网格
5. **三横键换源** —— 从直播页搬过来

### 注意事项

- **解析要容错**：页面改版会让正则失效。参考影视页的做法——
  失败时记详细日志（哪个 URL、哪一步、返回了什么），不要静默失败
- **播放地址可能带时效**：`main_url` 里有 `x-expires` 之类的参数，
  所以**每次播放都重新取**，不要长期缓存地址（和直播那个 StreamCache 不同）
- **海报走 `douyinpic.com`**：有 Referer 校验的可能，加载失败要能回退
- **竖屏 720x1280**：电视上是横屏，播放页要把两边利用起来（放选集/换源）

## 四、验证脚本

`build/hg_verify.py`（一次性脚本）记录了完整的探测过程，
包括括号配平提取 `video_player_info` 的方法。
`build/hongguo_sample.html`（分类页）、`build/hongguo_detail.html`（详情页）、
`build/hongguo_player.html`（播放页）是三个页面的样本，实现时可直接对照。
