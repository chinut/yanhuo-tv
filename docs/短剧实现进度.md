## 二、待做 ⬜

### 1. 详情页验证（未测）

代码已接好（走 `HongguoSource.loadSources`），但**没实际验证过**。
要看的点：

- 分集列表是否正确显示全部集数（该显示"共 72 集"）
- 免费集的地址是否真的取到（日志 `《剧名》：共 N 集，已取到地址 M 集`）
- 海报 / 标题 / 简介是否正常

**入口**：短剧板块 → 下移 → 确定进详情。

### 2. 播放 + 一集播完自动下一集 ⬅ **用户最关心**

现状：`VodPlayerScreen` 支持 `request.episodes` 列表和 `onSwitchEpisode` 回调，
但**没有接"播完自动下一集"**。

短剧的剧集很短（1~2 分钟），所以这个体验是核心。

**要做的**：
- 监听 `Player.STATE_ENDED`
- 自动切到下一集（构造新的 `PlayRequest` 走 `onSwitchEpisode`）
- 最后一集播完停在结尾（不要循环回第一集）
- 老电视上要注意：切集时先把当前 player 释放干净，别两个 player 抢资源

**注意**：`VodPlayerScreen` 是影视和短剧**共用**的。
影视不该自动连播（一部电影播完就结束），所以要加个开关，
或者按 `request.episodes.size > 1 && 是短剧` 判断。

### 3. 未取到地址的集要给友好提示

`HongguoSource` 把免费集之外的 `Episode.url` 留成空串。
播放器遇到空地址不能崩，要给明确提示（例如「该集需要红果 App 才能看」）。

## 三、踩过的坑（别重复踩）

### 1. 分集列表是懒加载的

详情页 DOM 里**只有 2~3 个 `<a>`**，但 `vid_list` 有 72 个。
滚动、"查看全部"都无效。

→ **不要解析 DOM**，直接正则抽 `"vid_list"` 数组。

### 2. 取播放地址必须用普通 GET，不能用浏览器

| 方式 | 结果 |
|---|---|
| 普通 GET（OkHttp / urllib） | SSR 里有 `main_url` ✅ |
| 真实浏览器（Playwright） | 视频变成 `blob:`（MSE），取不到 ❌ |

**反直觉，但是实测结果。**

### 3. 没有内容 API

截获的 15 个 JSON 全是统计/config：
`mcs.zijieapi.com`、`abtestvm.bytedance.com`、`safe.usergrowth.com.cn`、`zlink.toutiao.com`。

不用再找接口了，就是爬 HTML。

### 4. 详情页 HTML 大小会变（255KB / 470KB）

SSR 内容不完全稳定 → 解析要容错，失败要留日志。

### 5. 免费集限制是正常的付费墙

`accessible_episode_cnt` = 免费集数（实测 3）。
超出的播放页返回 **404**。这是正常现象，不要当异常处理。

### 6. 一次成功 ≠ 可复现

第一版文档写"链路已验证通"，但那只验证了**一次 Python 请求**，
没验证真实浏览器环境 —— 结果用浏览器打开时 `main_url` 根本取不到。
**教训：验证要说清"在什么条件下验证的"。**
