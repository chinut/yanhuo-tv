# 焰火TV 开发进度与待办

## 网络遥控（手机 App 当遥控器）

### 协议
HTTP + JSON，复用局域网服务端口（默认 8899）。**不需要 WebSocket** ——
手机端已经会发 HTTP，加长连接要多一套重连/心跳，对遥控这种低频场景不值得。
事件回显用**长轮询**（`events?wait=15000`）实现。

接口：`/api/remote/{ping,status,key,text,volume,mute,events}`

### 关键设计：传**键码**而不是语义动作
协议传的是 Android KeyEvent 键码，不是"上一项/下一项"。
因为电视端每个界面有自己的按键语义（首页=移焦点、播放页=换台/调进度、
搜索页=字母输入）。传键码**天然继承全部现有行为**，零维护成本；
手机端只要做一个虚拟遥控器按键布局，不用理解任何界面逻辑。

### 修了一个大问题
`DebugWebServer` 定义了却**全项目没有任何地方调用 `start()`** ——
也就是说"手机网页调试"这个功能一直是死的，设置页那句"服务运行中"是假的。
现在在 `BawanApp.onCreate` 按设置拉起（放 Application 而不是 Activity：
遥控要在任何界面都能用，且退到后台不该断）。

### 实测（全程只用 HTTP 请求，模拟手机操作）
```
down → left → right → ok   全部 consumed:true，无崩溃
```
并且成功用 HTTP 请求从首页导航进了影视库。
音量：8 → 5 → 静音(0) → 恢复(5)，与系统媒体音量一致。

### 交接给另一个工程的文件
`docs/for-other-project/`
- `README-网络遥控协议.md` —— 协议说明 + 接入步骤 + 常见问题
- `YanhuoRemote.kt` —— **零依赖客户端**（JDK + org.json），拷进工程改 package 即可用
打包件：`docs/焰火TV-网络遥控-交接包.zip`

## 本版（准备上真机测试）：影视以低端影视为核心

### 架构调整
之前是"聚合各源 → 用户想搜什么搜什么"，两个问题：每次进页面都要联网重抓（慢、断网就空白）；
用户面对搜索引擎得先知道自己想看什么（电视上难用）。

现在改成**内容驱动**：
- **低端影视 = 内容基础**。片库整份缓存在本地（``unified/LibraryStore.kt``），
  进影视页**立刻有内容**，联网只是"补货"；断网也照样能浏览和播放已缓存的条目。
- **TVBox = 辅助补充源**。只在"低端影视播不了 / 没有这部片"时，
  按片名去 TVBox 站搜同一个作品，作为备用线路追加进来。

### 关键实现
``LibraryStore``
- **分类型抓取**（movie / series / anime / variety 各 5 页）：
  官方 ``/movies`` 是混合流，而连续剧更新频率远高于电影，不分类的话
  前几页全是剧、电影被挤到很后面。分类抓保证每类都有内容。
- 行式文本存储（U+001F 分隔 + 转义），不用 JSON、不放 SharedPreferences
  （后者是整份读进内存的 XML，几千条会拖慢启动）。
- 抓取失败时**保留旧库**，不把好缓存冲掉。

``MovieAggregator.buildPlayableSources``
- **低端影视永远排第一**（详情页第一个按钮就是最靠谱的线路）
- 只在"自己没有可播源"时才去补充，避免每次开详情都联网
- ``supplementSources`` 按**归一化标题**匹配（``normalizeTitle``），
  避免「片名(国语)」这类差异导致漏配

播放失败自动换源
- ``UnifiedVideoScreen`` 新增 ``onPlaybackFailed(failedFlag)``
- ``BawanRoot`` 收到后自动挑一个"没试过且有剧集"的源重新起播，
  用 ``autoSwitching`` 防递归

### 设置页新增
- 「影视内容来源」卡片：**允许 TVBox 作为补充源**开关（``prefs.tvboxSupplement``）
  + 显示本地片库条数 + 「清空片库」
- 低端影视域名仍在上方「板块 C」卡片里改（原有功能）
- 影视订阅卡片的说明改成"这些站点只是备用线路，不参与主内容列表"

### 卡顿修复
``VodPlayerScreen`` 的 ExoPlayer 改用自定义 ``DefaultLoadControl``：
起播前攒 20 秒缓冲、re-buffer 后 35 秒、最小 25 秒 / 最大 90 秒；
网络超时放宽到 15s/30s；HLS 开 ``setAllowChunklessPreparation(true)``。

**思路是用启动延迟换播放流畅** —— 低端影视是 HLS 分片流，默认配置下
某一段下载慢就见底卡一下。电视用户对"开头转圈两秒"的容忍度远高于"看着看着卡"。

> 注意：**模拟器上的卡顿有一部分是模拟器自身问题**（``-gpu auto`` +
> ``ro.hardware.egl=emulation``，控制台一直刷 ``no frame!``），
> 真机表现应该好于模拟器。如果真机仍卡，优先怀疑网络带宽而非代码。

### 实测
- 首次安装清数据后：分类型抓取跑通，**390 部**入库，进度日志正常（补货 13/20）
- 类型筛选栏正常（选项来自库里真实分类，不写死）
- 海报 URL 全部有效，空白处只是**图片尚在下载**（390 张首次较慢）

### 未能实测
- 播放流畅度改善（模拟器无法作为依据）
- 播放失败自动换补充源（需要构造一个确定失败的源）

## 用户反馈的 8 个问题：定位与修复

### 根因（一次修好 3 条）
`TvFocusManager.move()` 用元素的**实际屏幕坐标**算方向距离，
而懒加载容器里**屏幕外的项不参与布局**，`boundsProvider()` 返回空矩形被跳过
→ 找不到候选 → `return false` → **按键完全没反应**。

而且 `TvFocusScope` **从未被注册**（`ProvideTvFocus` 调用时没传），
所以本来设计好的"滚动兜底"一直是死代码。

修法（`ui/theme/TvFocus.kt`）：
- `move()` 拆成 `move`（带兜底）+ `step`（纯几何）
- 几何找不到候选时，先调 `TvFocusScope.scrollViewport(direction)` 滚一点，**再试一次**
- 新增 `RegisterViewportScroll { delta -> state.scrollBy(delta) }`，滚动容器自己注册
- `BawanRoot` 真正创建并传入 `TvFocusScope`

对应问题：**#2 影视左键没用**、**#3 瀑布流不能下滚**、**#6 滚轮能滚方向键不能**。

### 自动化焦点探针（本轮新增工具，解决"测不了"的问题）
`build/pytest/probe3.py` —— 从截图判断首页焦点在哪一块。

**原理**：自绘焦点用 uiautomator 读不到，只能靠像素；但**不能扫整个区域** ——
直播画面本身就是蓝的，会污染检测（踩过）。
做法是**只扫每个块的外缘左边线**（约 8px 宽的竖条），并收紧颜色容差。

校准结果（三张已知答案的图，互不干扰）：

| 图 | 探测结果 | 命中像素 |
|---|---|---|
| 直播聚焦 | `focus=LIVE` | 125 |
| 影视聚焦 | `focus=MOVIE` | 79 |
| 设置聚焦 | `focus=SET` | 26 |

关键坐标：三个块的左边框都在 **x=1053–1060**（一开始猜的 1064 是错的，
扫一遍像素才找到）。

| DOWN | MOVIE ✅ |

### 遥控器方向键路径：实测走查记录

**方法**：`adb shell input keyevent <19/20/21/22/23>` + 截图核对**焦点边框颜色**
（蓝=直播、粉=影视/一般项、绿=设置）。自绘焦点用 uiautomator 读不到，
只能靠边框颜色判断焦点位置 —— 这也是这次专门做亮边框的额外好处。

#### 首页（已实测，通过）
| 操作 | 结果 |
|---|---|
| 直播 → 下 | 影视（粉框）✅ |
| 影视 → 左 | 直播（蓝框）✅ |
| 直播 → 右 | 影视 ✅ |
| 影视 → 下 | 设置（绿框）✅ |

查出并修复的两个 bug：
1. **`onLeft` 指向不存在的 key**：`MovieEntry`/`SettingsEntry` 写着
   `moveTo(FocusKeys.nav("home"))`，但**全 App 没有任何地方注册这个 key**

   **按键被消费却什么也不发生** —— 几何导航永远没机会执行。
2. **几何导航在"等宽上下排列"时挑错目标**：从直播按「下」会跑到「设置」，

### #1 选中框不够明确（已彻底改为亮边框）
用户原话：「太难辨认了 老人没法用啊啊」。

**为什么前几版都不行**：我一直用「光晕」表达焦点（外层柔和光斑 + `shadow` 外发光）。
设计上更高级，但电视上根本认不出来：
- 电视有 overscan、亮度对比度普遍不如显示器
- **光晕是渐隐的，没有明确边界** —— 眼睛抓不住"从哪到哪是选中的"
- 深色 UI 上光晕本来就不显眼

**最终做法**：`Modifier.focusBorder(...)` —— 一条 **4dp 实心亮边**。
- 用 `drawWithContent` 画在**内容之上**：Compose 的 `Modifier.border` 画在背景之上、
  内容之下，而卡片用了半透明的 `frostedGlass`，会把边框冲淡
- **纯色**不用渐变（渐变会让边在某几段变暗）
- 未聚焦时完全不画，避免满屏都是线

首页三块的边框颜色按模块区分：直播=蓝、影视=粉、设置=绿；
同时把光晕从 18dp 提到 30dp 作为辅助。

> 注意：`FocusHalo` 组件**从未被任何界面调用**，实际焦点样式在 `tvFocusable` 里。
> 改样式要改那边，别被这个孤儿组件误导（已确认）。

### #1 选中框不够明确

### #8 "no frame" 窗口是什么（重要）
模拟器启动参数是 `-gpu auto`，且 `ro.hardware.egl=emulation`、
`debug.hwui.renderer=skiagl`。那个刷 `no frame!` 的控制台窗口是
**模拟器的 GLES/ANGLE 翻译层在报错**：宿主 GPU 没能正常出帧。

- **不是你 App 的窗口**，不会出现在真实电视上
- 但它会让模拟器渲染降级，**视频播放失败/卡顿会明显增多**
  → #7「大量视频无法播放」有相当一部分是这个原因，不全是代码问题
- 建议改用软件渲染重启模拟器：`emulator -avd BawanTV_TV -gpu swiftshader_indirect`
  （注意：`-no-audio` 会让声音消失，`-audio wasapi` 会让模拟器崩，别加）

## 2026-10 这一轮：多分辨率适配 + 拼音搜索

### 多分辨率适配（全量完成）
以 1080p@320（逻辑 960×540）为基准，取**短边**算缩放系数，钳制 0.75~3.2，
经 `ProvideResponsive` 用 CompositionLocal 下发（挂在 MainActivity 根布局）。
用法 `116.dp` → `116.sdp`，`28.sp` → `28.ssp`；设计令牌用 `Txt.Section.ssp`。

**实测四种配置，界面比例完全一致：**

| 模拟配置 | 逻辑尺寸 | scale |
|---|---|---|
| 1920×1080 @320 | 960×540 | 1.0 |
| 3840×2160 @320 | 1920×1080 | 2.0 |
| 3840×2160 @640 | 960×540 | 1.0 |
| 7680×4320 @640 | 1920×1080 | 2.0 |

迁移踩坑记录（都已修）：
- `border()` / `shadow()` / `elevation` **不缩放** —— 绝对视觉量，放大会变粗变脏
- `Modifier.blur()` 要编译期常量，不能吃 @Composable 属性，保持普通 dp
- `Dp.sdp` 扩展做不了：`Dp.value` 就是 Float，会和 `Float.sdp` 撞 JVM 签名
- 用脚本批量替换后 **import 块被搞乱**（重复、通配符被顶掉）→ 需按**序数**排序重建，
  否则 `key.*` 会排到 `key.Key` 前面导致符号解析失败

电视的 dpi 差异极大，同一份界面写死 dp 会出问题：

| 屏幕 | density | 逻辑尺寸 |
|---|---|---|
| 1080p | 320 | 960 × 540 |
| 4K | 320 | **1920 × 1080** ← 逻辑空间翻倍 |
| 4K | 640 | 960 × 540 |
| 8K | 640 | **1920 × 1080** |

所以新建 `ui/theme/Responsive.kt`：以 1080p@320（960×540）为基准，取**短边**算缩放
系数（兼容带鱼屏），钳制在 0.75~3.2，通过 `ProvideResponsive` 用 CompositionLocal 下发。
挂在 `MainActivity` 根布局。用法：`116.dp` → `116.sdp`，`28.sp` → `28.ssp`。

**注意进度**：基础设施 + 首页已迁移；其余页面（影视、设置、直播墙、播放页）
目前仍是固定 dp，在 4K@320 上会显得偏小，**待迁移**。

### 开屏 → 首页：预热 + 交叉淡化
以前开屏一结束就切首页，于是用户会看到「直播区黑着、海报墙空着，过一两秒才补上」。

现在分两步解决：

**1. 开屏期间并行预热**（`ui/HomeWarmup.kt`）
开屏动画播放的同时，后台把首页要用的东西备好：直播频道表解析 + 海报片单拉取 + 图片预解码。
结果缓存在 `HomeWarmup` 里，首页挂载时直接取用，不重复解析/请求。

**2. 交叉淡化交接**（`MainActivity`）
时序刻意这样排：

`
0s ──────────── 开屏动画（焰火飞行）──────────┐ 开屏淡出 460ms
0s ── 首页在下面同步渲染（被盖住）───────────┤
                                             ↓  只剩首页
`

要点：**首页在开屏还完全不透明的时候就已经挂载并渲染好了**，只是被盖着。
等开屏淡出时底下早就是画好的首页 —— 整个过程两屏都有内容，
不会出现「开屏没了、首页还没画出来」中间闪一下黑底。

时长：动画 700 + 450 + **焰火飞行 3400**（从 2600 拉长）≈ 4.6s；
再加缓冲 —— `minSplashMs = 3.6s`（至少播这么久，否则一闪而过很难看）、
`maxSplashMs = 7.5s`（网络再差也不让用户干等，到点就走，首页后续自己补）。

### 动态极光背景（让毛玻璃"有东西可透"）
毛玻璃的本质是**透出后面的东西** —— 背景是死的，玻璃就没有内容可透，
看起来只是一块半透明灰板。所以背景必须动起来：

`AuroraBackdrop`（`ui/theme/Surfaces.kt`）
- 3 团大半径径向渐变光斑，沿**不同相位的正弦轨迹**缓慢漂移
  （周期 28/37/45 秒 —— 电视长时间开着，动快了非常烦人）
- 相位错开，避免三团同步移动（同步看起来像整块图在漂）
- 一团高光做 11 秒的**呼吸**（透明度起伏），避免画面"死平"
- 顶部一道极淡斜向光带，给画面一个光源方向
- 26 个极淡星点缓慢横移（确定性伪随机，不用 Random，保证每帧不闪）

**刻意不用 `Modifier.blur()`**：大半径模糊在 TV 的 GPU 上开销大、容易掉帧；
径向渐变本身就是柔和的，每帧只改位置，成本只有几个 `drawCircle`。

### 毛玻璃（iOS 风格）
`Modifier.frostedGlass`。先说明一个技术事实：**Compose 做不到"采样背后内容再模糊"**，
它是单向绘制的；API 31+ 的 `RenderEffect` 只能模糊自己、不是背后。
所以用 iOS 大量控件同款的**叠加式玻璃**（`minSdk 24` 全版本可用）：
半透明底色 + 极淡白色渐变 + **1dp 亮色顶部描边**（这一笔是"像玻璃"的关键）。

### 首页海报墙秒开（持久化缓存）
以前每次冷启动都要「聚合接口 → 合并 → 下图」三步，那块会空好几秒。
现在：
- 抓到的片单**落盘**（`AppPrefs.homeMovieCache`，只存精简字段）
- 进界面**先用缓存即时渲染**（海报命中 Coil 磁盘缓存 → 立刻出来），后台再刷新替换
- 开屏那两三秒里顺带 `preloadPosters()` 预热，进首页不会白一下

### 网页播放清理：顶部导航栏兜底规则
央视频那类站点会在播放器上方留一条**白色菜单栏**（央视频/推荐/电视/赛事…），
它既不是 fixed 也没有高 z-index，原有选择器压不住。
新增兜底判据：**位于顶部区域 + 宽过屏幕一半 + 背景为浅色（三通道 >200）** → 判定为站点导航，隐藏。

### 视觉语言（重做过一次）
之前是「纯色灰底 + 一圈亮描边」，满屏都是线、平面色块没有纵深，很"工程感"。
现在抽了 `ui/theme/Surfaces.kt` 作为设计基元：

- **纵向渐变底**（上亮下暗）制造光照感，替代一块平色
- **高光内描边**模拟玻璃厚度（顶部一道极淡的横向反光）
- **焦点用光晕 + 轻微上浮 + 亮度提升**表达，不再是一圈刺眼实线
- `AmbientBackdrop` 给整页铺两团极淡的冷/暖光斑，替代纯色背景
- 底色从近黑改成带蓝紫的深夜色（纯黑在电视上显廉价），圆角整体加大

### 首页 = 推荐墙（不再是左右重复的文案 + 菜单）
以前首页左边一大段宣传文案、右边三个入口按钮，左右其实是一回事，整屏没几个能点的。
现在改成真正的电视推荐墙，进来就是一格一格可直接点开的内容：
- **正在直播**：内置频道表前 14 个台，确定键直接起播（老电视「一按就是台」）
- **低端影视**：官方接口最新更新，带海报
- **影视订阅推荐**：当前 TVBox 站点的首页推荐

三块各自独立加载，谁先回来谁先上墙；点海报会切到影视板块并**直接打开那部作品的详情**。
三个板块入口保留成顶部一行快捷键。

### 播放一律全屏（电视不是网页）
VOD / 低端影视的播放页现在是**独立全屏 Popup 窗口**。
以前它们直接画在影视板块的内容区里，而内容区外面还有左侧导航栏和 overscan 安全边距，
所以在电视上播起来是「小窗口 + 四周留白」。现在播放时整屏都是画面。

### 界面清理
- **所有 App 内的「返回」按钮/返回条全部移除** —— 遥控器上本来就有返回键
- **设置页二维码弹窗修好了**：以前是全屏 Dialog 且 `onDismissRequest = {}`，

### 直播播放界面（已重绘）
原来的问题是「底部整条全景浮层 + 右侧一个独立小卡片」，两块各画各的、视觉割裂。现在统一成一套语言：

- **左下角台标卡**：圆角玻璃底 + 细边框，只放「台号 + 台名 + 分组/进度/源」和遥控器方向键图形。
  **去掉了「确定」「返回」这类文字提示** —— 遥控器上本来就有这些键，写出来只占地方。
- **右侧频道列表**：同款玻璃底 + 圆角 + 细边框，当前频道用「左侧高亮竖线 + 渐变底 + 白字」
  三重标记，并自动滚动到可视区靠上 1/3 处（往下换台时能提前看到后面几个台）。
- 两块动画时长一致（140/200ms），从屏幕边缘滑入，读起来像一个整体。

### 换台表 = 全部频道（像老电视一样循环）
换台列表从「当前分组」改成**跨分组合并、按台名去重的整表**（实测 507 个台）：
上下键能一路从央视换到地方台，走到头自动绕回第一个。
- 去重时会**把同名台的备用源并进保留的那条**，避免去重丢源
- 首页点直播、直播板块点台，用的都是这张整表
- 合并来源后同名台会有多条，不去重的话同一个台会出现两次

### 内置频道表

- 播放页 `live/LivePlayerScreen.kt`：播放中 ↑↓ 换台、←→ 调音量、确定键呼出台标浮层、返回退出

**两条播放路线（按频道地址自动选择）**：
1. **直连流**（`.m3u8` / `.flv`）→ ExoPlayer，可按域名补 Referer/UA
2. **电视台网页**（央视网、各省台直播页）→ `live/TvWebPlayerView.kt`：用浏览器引擎打开电视台的直播页，
   让网页自己的播放器解码 —— 央视那类**加密专有流**只有它们的网页播放器能解，
   交给 ExoPlayer 必然报 `PARSING_MANIFEST_MALFORMED`

让路线 2 成立的三处关键点（都已实测确认）：
- **页面 UA 用桌面版**：移动 UA 下页面拿到的是不带 CORS 头的流地址，CDN 会拒绝跨域；
  桌面 UA 下页面能正常解析出真实 m3u8
- **原生层给流请求补 `Origin`/`Referer` + CORS 响应头**（`shouldInterceptRequest`）：
  这是「网页能播、原生直连播不了」的根因
- **注入「只看视频」脚本**：把 video 及其祖先链铺满全屏、隐藏其它兄弟节点，
  轮询清理进度条/EPG/水印/遮罩并关闭浏览器自带控件 → 电视上看到的是干净的一个台

实测结果：**CCTV-13 新闻 ✅、CCTV-2 财经 ✅ 正常直播**，连续换台正常。
